The Problem & The Solution

Developers grant wildcards because AWS has 14,000+ IAM action names. Overprivileged policies make it into staging and production, creating massive compliance failures and breach vulnerabilities.

❌ The Wildcard Anti-Pattern

CRITICAL RISK

Commonly committed to bypass "Access Denied" errors:

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "*",
      "Resource": "*"
    }
  ]
}

⚠️ Violates CIS Benchmark 1.16 & NIST SP 800-53 AC-6.
⚠️ Allows shadow privilege escalation and full data lake exfiltration.

✅ Synthesized by iam-shrink in 0.2s

How It Works: Zero-Credential Observation

`iam-shrink` does not require AWS credentials, an internet connection, or deploying to an AWS account. It observes real SDK telemetry locally over loopback UDP.

1

Run Test Suite

Prefix your existing test command with iam-shrink run -- <cmd> (Go, Python, Node.js, Java).

2

CSM Loopback UDP

AWS SDKs natively broadcast microsecond telemetry packets to loopback port 127.0.0.1.

3

Correlation & Mapping

The engine maps runtime API operations to exact IAM action names and parameterizes target ARNs.

4

Multi-Format Policy

Emits production-grade Terraform HCL, AWS CDK, GCP Custom Roles, or Azure RBAC instantly.
